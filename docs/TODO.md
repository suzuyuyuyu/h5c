## h5c

- [x] クロス言語テスト（`test/test_crosslang.c`）
    - 素の HDF5 C API だけで参照ファイルを組み立て、次元順序・ディスク上の型・
      bool の enum メンバ・文字列の SPACEPAD・インターリーブのバイト配置・
      ゼロ長 extent を固定する。参照 `.h5` はコミットしない。
    - `h5fortran` の実出力があればそれとも突き合わせる（無ければスキップ）。
- [x] 可視化 writer（`h5c_viz.h`、`src/h5c_viz.c`）
    - `scheme_version = 1`。`h5xdmf` が `h5c` の出力から XDMF3 を生成できることを
      実測で確認した。int8 / int16 を追加した。
    - real128 は非対応とした。C では `__float128` というコンパイラ拡張が必要で、
      実用例もないため。詳細は `docs/FORMAT.md`。
- [!] 配列属性
    - 値が配列の属性。現在は文字列と数値スカラーだけ対応している。
      可視化のメタデータは短いベクトルになりがちで（領域の境界、原点、格子間隔）、
      回避策は「小さい dataset にする」「スカラー属性を並べる」「文字列に詰める」の
      どれかで、どれも不自然である。
    - 型の仕組みは既にあるため、`h5c_write_attr_scalar` の隣に長さ引数付きの版を
      足すだけで済む。
    - `h5fortran` の公開属性 API は**文字列のみ**（`t_hdf5_attr` は
      `name: char(64)` と `value: char(256)`）。数値属性は可視化 writer 内部の
      private helper（`write_int32_attribute_` / `write_real64_attribute_`）で
      書いており、公開されていない。したがって配列属性は `h5fortran` にもなく、
      これは h5c 独自の追加になる。
- interleaved 書き込みの pack と strided hyperslab の性能比較
    - 現在は連続 I/O を優先して、独立した成分配列をタイル単位で pack している。
    - 実際の並列ファイルシステム上で、現在の方式と成分ごとの collective strided
      write を同一条件で測定する。read-modify-write の発生有無、pack 時間、
      `H5Dwrite` と close/flush の時間を分けて確認し、実装変更は測定結果を見て判断する。
    - **chunking もここで一緒に測る。** chunk が必要になるのは圧縮をかけるとき、
      UNLIMITED dataset を作るとき、そして並列ファイルシステムのストライプ境界に
      書き込みを揃えたいときである。圧縮も UNLIMITED も不要なので、残る価値は
      3 つ目だけで、これは測らないと効くか分からない性能項目である。
      独立した TODO 項目としては扱わない。
- [?] 複数次元の同時分割
    - `dims[0]` だけをランク間で分割する。3 次元格子を `Px × Py × Pz` の
      プロセス格子に分けて各ランクが全方向で部分ブロックを持つ形は、
      `__partition__` が 1 次元の境界配列である以上表現できない。
    - 構造格子の差分法では普通だが、MPM の粒子も非構造格子の cell/node も
      本質的に 1 次元のリストなので、現在の用途では不要と判断している。
      実需が出たらフォーマット自体の再設計になる。
- [?] `uint` 系と `float16`
    - 実需が出てから追加する。型を増やすコストは enum と写像テーブルの各 1 行。
- [?] real128
    - `h5fortran` は geometry と field で対応している。C では Fortran の real128
      （IEEE binary128）に相当するのが `long double` ではなく `__float128` という
      コンパイラ拡張になるため、可搬性を理由に見送っている。
    - `h5fortran` が real128 で書いた dataset は `H5C_TYPE_UNKNOWN` として読まれる。
      実際にそれを読む必要が生じたときに判断する。

## 対応しないと決めたもの

- **圧縮**。要求がない。必要になれば chunking と合わせて上記の測定項目で扱う。
- **Parallel の文字列 I/O**。要求がなく、`h5fortran` も未対応。

## 検証されていないこと

- 並列テストは 4 ランクまでしか実行していない。大きなランク数、複数ノード、
  実ファイルシステム性能は未確認。

  2 対 4 のタイル数になる条件）で担保しているが、合意を壊したときに実際に
  デッドロックすることは確認していない。
